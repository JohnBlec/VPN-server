# Управление VPN

Все команды выполняются в `/opt/aegis-vpn`. Они обращаются к локальному API из контейнера;
токен берётся из Docker secret и не попадает в аргументы процесса.

## Устройства и конфигурации

Один peer — одно устройство, отдельный ключ и адрес. Не используйте один профиль
одновременно на нескольких устройствах. ID задавайте стабильный и уникальный:
например `customer-42-phone`, а при интеграции сайта — UUID записи устройства.
В ID допускаются латинские буквы, цифры, `_` и `-`, максимум 64 символа.

```bash
docker compose exec -T vpn python3 /opt/aegis/agent.py create customer-42-phone --name 'Телефон клиента 42'
docker compose exec -T vpn python3 /opt/aegis/agent.py list
docker compose exec -T vpn python3 /opt/aegis/agent.py get customer-42-phone
```

Повтор `create` с тем же ID и тем же именем возвращает существующее устройство:
новые ключи и адрес не создаются. При несовпадающем имени ответ будет `409`.

Скачать или повторно скачать конфигурацию:

```bash
umask 077
docker compose exec -T vpn python3 /opt/aegis/agent.py config customer-42-phone > exports/customer-42-phone.conf
test -s exports/customer-42-phone.conf
```

Проверяйте код возврата команды перед передачей файла: shell создаёт файл даже при ошибке.
При отключённом устройстве или несинхронизированном сервере скачивание отклоняется.
API и CLI не генерируют QR: сайт сможет сформировать QR из этого же текста `.conf`
локально. Не отправляйте конфигурации в сторонние онлайн-генераторы QR.

## Отключение, возобновление и отзыв

```bash
docker compose exec -T vpn python3 /opt/aegis/agent.py disable customer-42-phone
docker compose exec -T vpn python3 /opt/aegis/agent.py enable customer-42-phone
```

`disable` удаляет peer из работающего интерфейса, сохраняя его ключи в состоянии.
Поэтому ранее скачанный профиль перестаёт подключаться, а `enable` восстанавливает
работу того же профиля. Это операция для окончания/продления подписки.

Полный отзыв:

```bash
docker compose exec -T vpn python3 /opt/aegis/agent.py delete customer-42-phone
```

`delete` удаляет запись и клиентские ключи из текущего состояния; старый профиль
больше не работает. Повторное удаление безопасно. Для нового устройства используйте
новый ID. Старые резервные копии могут содержать отозванные ключи: после восстановления
обязательно сверяйте состояние со списком подписок/отзывов сайта до открытия VPN клиентам.

## Изменение адреса, порта и DNS

1. Сделайте бэкап.
2. Измените `VPN_ENDPOINT`, `VPN_PORT`, `VPN_DNS` или `VPN_MTU` в `.env`.
3. Для нового UDP-порта обновите firewall провайдера и хоста.
4. Примените: `docker compose up -d --force-recreate --wait vpn`.
5. Скачайте профили заново и обновите их на устройствах.

Серверные и клиентские ключи сохранятся, но **уже импортированные файлы на телефонах
не обновляются автоматически**. При смене только IP за тем же DNS-именем может потребоваться
перезапуск подключения и ожидание DNS TTL.

Внутренний UDP-порт контейнера всегда 51820; `VPN_PORT` меняет внешний Docker port mapping
и поле Endpoint в выдаваемых файлах. Порт API также меняется в `.env` (`AGENT_PORT`),
после чего нужно обновить SSH `PermitOpen` и настройки туннеля.

`VPN_SUBNET` и параметры обфускации сохраняются при первом запуске. Обычный restart
их не меняет. Не редактируйте `data/state.json` во время работы. Смена подсети/версии
протокола — отдельная миграция с бэкапом и проверкой совместимости профилей.

## Проверка состояния

```bash
docker compose ps
docker compose logs --tail=100 vpn
docker compose exec -T vpn python3 /opt/aegis/agent.py health
docker compose exec -T vpn awg show awg0 latest-handshakes
docker compose exec -T vpn awg show awg0 transfer
```

Не публикуйте `awg showconf`, `awg show ... dump`, содержимое `.conf`, `state.json`
или Docker secrets: они могут раскрыть ключи. Обычные команды выше не выводят приватные ключи,
но публичные ключи и статистика всё равно относятся к данным ваших клиентов.

Проверка CRUD без передачи конфигурации пользователям: `bash scripts/smoke-test.sh`.
Она создаёт собственный временный peer и удаляет только его. Реальный VPN-трафик этот
тест не проверяет.

## Перезапуск и отказ

- `docker compose restart vpn` — кратковременное прерывание соединений, данные сохраняются.
- `docker compose stop vpn` / `docker compose start vpn` — остановка и запуск без удаления.
- При падении VPN-процесса контейнер завершается, Docker запускает его заново.
- `unhealthy` сам по себе не перезапускает контейнер. Проверяйте логи и причину отказа.
- Контроллер раз в 15 секунд сверяет конфигурацию. Ручные изменения через `awg set`
  будут перезаписаны; используйте API/CLI.
- Ответ `503` после изменения означает: желаемое состояние уже сохранено, но применение
  не подтверждено. Повторяйте запрос с тем же ID, не создавайте новый peer.
