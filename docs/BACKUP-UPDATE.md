# Резервные копии, обновление и восстановление

Команды выполняются в каталоге Compose VPN. В примерах — `/opt/aegis-vpn`;
для установки в `/root/VPN-server` или другом месте замените команды `cd` своим путём.

## 1. Ключ бэкапов — отдельно от VPS

На доверенном компьютере с установленным `age`:

```bash
age-keygen -o aegis-backup-identity.txt
```

Сохраните секретный файл в менеджере секретов/на отдельном носителе. В выводе будет
публичный получатель `age1...`. **На VPN-сервер передаётся только получатель**, а не секретный
файл. Потеря identity делает зашифрованные бэкапы невосстановимыми.
Источник: [age](https://github.com/FiloSottile/age).

На VPS:

```bash
cd /opt/aegis-vpn
bash scripts/backup.sh age1YOUR_PUBLIC_RECIPIENT
```

Скрипт на короткое время останавливает VPN для согласованной копии и запускает ранее
работавший контейнер после завершения, в том числе при ошибке архивации. Если VPN был
остановлен до бэкапа, он останется остановленным. В выводе будет путь к `.tar.gz.age`.

Архив включает `data/`, оба секрета, `.env`, Compose/Dockerfile, код контроллера и ID
текущего образа. Открытый tar-файл на VPS не создаётся: поток сразу шифруется.
Экспортированные клиентские файлы не включаются — их можно получить повторно из состояния.

Скопируйте готовый `.age` за пределы VPS. Бэкап на том же диске не защищает от потери
VPS. Для сайта отдельно резервируйте PostgreSQL, его секреты и настройки: этот архив
содержит только VPN-часть системы.

Для регулярного запуска используйте системный таймер/планировщик с этой же командой,
учитывая краткий перерыв VPN. Публичный age-recipient не является секретом.
Проверяйте код выхода, наличие архивов и свободное место; автоматического удаления старых
бэкапов комплект не выполняет. Периодически делайте пробное восстановление на отдельном VPS.

## 2. Обычное обновление без переустановки

Пример для обновления приложения/образа, которое сохраняет формат `schema=1`:

```bash
cd /opt/aegis-vpn
bash scripts/backup.sh age1YOUR_PUBLIC_RECIPIENT

# Запомнить работающий образ для быстрого отката.
rollback_tag="rollback-$(date -u +%Y%m%dT%H%M%SZ)"
container=$(docker compose ps -q vpn)
image=$(docker inspect -f '{{.Image}}' "$container")
docker image tag "$image" "local/aegis-amneziawg:$rollback_tag"
printf 'Rollback image tag: %s\n' "$rollback_tag"
```

Обновите **только файлы приложения** из новой версии проекта. Сохраните `data/`,
`secrets/`, `.env`, `exports/`, `backups/`. Не запускайте `setup.py`.
В `.env` задайте новый `VPN_IMAGE_TAG`, например `2026.10.01-1`. Меняйте commit-версии
Amnezia только после изучения совместимости; обычное обновление сайта их не требует.

```bash
docker compose config --quiet
docker compose build --pull vpn
docker compose up -d --no-deps --force-recreate --wait --wait-timeout 120 vpn
bash scripts/smoke-test.sh
```

Проверьте подключение **ранее выданным** профилем с настоящего устройства. Сравните
публичный ключ сервера до/после через `awg show awg0 public-key`.
Бэкап и rollback-образ сохраняйте до завершения проверки. Не используйте без необходимости
`docker system prune -a`: команда может удалить сохранённый образ отката.

Здесь нет Watchtower и автоматического обновления `latest`: версия меняется управляемо.
Исходники протокола зафиксированы по commit, но базовые Debian/Go-образы и apt-пакеты
при `build --pull` могут обновляться. Для точного возврата храните старый собранный образ,
а не рассчитывайте только на повторную сборку Dockerfile.

## 3. Быстрый откат образа

Если новая версия не прошла проверку, верните прежние Dockerfile/Compose/код из вашей
версии проекта и прежние переменные окружения. Не затирайте актуальные `data/` и секреты.

```bash
VPN_IMAGE_TAG=rollback-YYYYMMDDTHHMMSSZ docker compose up -d --no-build --force-recreate --wait vpn
```

Подставьте реальный тег, сохранённый при обновлении. Для постоянного отката также
запишите этот тег в `.env`, иначе следующая команда без override выберет новую версию.

Если изменился формат состояния, откат одного образа недостаточен: нужна совместимая
копия данных. Восстановление старого состояния теряет более новые операции, включая
отключения/отзывы клиентов. Сверьте его с сайтом **до открытия UDP-порта**.

## 4. Восстановление на новом VPS

1. Установите Docker и проверьте TUN по DEPLOY.md.
2. Закройте публичный UDP-порт VPN на время восстановления. Сайт/очередь управления
   тоже приостановите, чтобы они не меняли восстанавливаемое состояние.
3. На доверенном компьютере расшифруйте **свой проверенный архив**:

```bash
umask 077
age --decrypt -i aegis-backup-identity.txt backup.tar.gz.age > restore.tar.gz
tar -tzf restore.tar.gz
```

4. Передайте `restore.tar.gz` на новый VPS через SSH/SCP. В root-сеансе создайте новый
   пустой каталог и распакуйте туда архив. Не распаковывайте поверх работающей установки:

```bash
install -d -m 700 /opt/aegis-vpn-recovery
test -z "$(ls -A /opt/aegis-vpn-recovery)" || { echo 'Recovery directory must be empty'; exit 1; }
tar --extract --gzip --file=/root/restore.tar.gz --directory=/opt/aegis-vpn-recovery --no-same-owner
chmod 700 /opt/aegis-vpn-recovery/data /opt/aegis-vpn-recovery/secrets
chmod 600 /opt/aegis-vpn-recovery/.env /opt/aegis-vpn-recovery/data/state.json /opt/aegis-vpn-recovery/secrets/*
cd /opt/aegis-vpn-recovery
install -d -m 700 exports backups
```

Архив содержит необходимые для образа `compose.yml`, `Dockerfile`, `.dockerignore`,
`agent.py`, `entrypoint.py`, `traffic.py`, а также весь `data`, включая `traffic.sqlite3`.
`.dockerignore` исключает секреты из контекста сборки.
Скрипты/документацию можно вернуть из той же версии репозитория, не заменяя восстановленные
секреты и состояние. Не держите одновременно два сервера с одинаковыми ключами и endpoint.

5. При необходимости измените в `.env` только новый внешний endpoint/UDP-порт.
   **Не генерируйте заново `secrets/client_key`**: иначе старые клиентские ключи не расшифруются.
6. Соберите зафиксированные исходники или загрузите сохранённый образ, затем запустите:

```bash
docker compose build vpn
docker compose up -d --wait --wait-timeout 120
docker compose exec -T vpn python3 /opt/aegis/agent.py list
```

7. Восстановите актуальные отключения/отзывы из системы учёта. Для подключённого сайта
   обновите SSH-туннель/known_hosts и копию токена при необходимости, сохраняя существующую
   запись VPNServer и ключи восстановленного агента. При остановленном фоновом worker
   выполните на сервере сайта `bash deploy/site.sh exec -T backend python manage.py vpnworker --once`,
   затем запустите единственный `vpn-worker` и проверьте `vpnworker --check`.
   Без интеграции проверьте и примените актуальный список вручную.
8. Разрешите UDP только с адреса тестового клиента и проверьте подключение, затем
   откройте UDP остальным клиентам. При смене
   endpoint скачайте и импортируйте обновлённые профили.
9. Уберите открытые копии архива после проверки; зашифрованный исходный бэкап сохраните.

Восстановление на прежнем VPS выполняется так же в новом каталоге после остановки старого
контейнера. Старый каталог сохраните до проверки. Имя Compose-проекта одинаковое:
не запускайте старую и восстановленную копию одновременно.

Статистика требует согласованных копий сайта и VPN. После восстановления старой
`traffic.sqlite3` сайт не уменьшает уже сохранённые итоги; новый трафик может не
учитываться, пока восстановленные счётчики не догонят их. Не удаляйте журнал
и не запускайте его копии на двух работающих VPN-хостах с одним `source`.

## Что делать при потере отдельных файлов

- Нет `data/state.json`, но есть `.initialized`: запуск специально остановится, восстановите
  согласованную копию данных. Удаление маркера создаст другой VPN, а не восстановит старый.
- Нет `secrets/client_key`: восстановите его из того же бэкапа. API-токен не заменяет этот ключ.
- Утёк только API-токен: сгенерируйте новый, согласованно обновите секрет сайта и
  пересоздайте VPN-контейнер. Клиентские VPN-ключи при этом не меняются.
- Утекли VPN-ключи/state: требуется отзыв затронутых профилей и при необходимости
  перевыпуск серверных ключей. Перезапуск контейнера утечку не устраняет.
