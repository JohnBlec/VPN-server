# Постоянный ретранслятор через Москву

Маршрут: клиент → московский публичный UDP-порт → иностранный AmneziaWG → интернет.
В Москве пересылаются зашифрованные UDP-пакеты; ключи, peers, отключение по подписке
и статистика остаются на иностранном агенте. Этот способ не создаёт второй VPNServer.

Проверенная в проекте пара: `62.113.42.137:14443/UDP → 83.171.225.80:443/UDP`.
Клиентское подключение и выход с иностранного IP были проверены вручную.

## Установка на Москве

Нужны root, systemd, Python 3, `ip`, `ss`, `iptables`, Docker с цепочками `DOCKER-USER`
и `DOCKER` (iptables backend, включая iptables-nft). Native nftables backend Docker
без этих цепочек пока не поддерживается: установщик откажется применять правила.
Оба VPS должны иметь публичный IPv4; московский адрес должен быть назначен входному
интерфейсу. Исходящий интерфейс определяется по маршруту к иностранному VPS.

Получите новый `scripts/relay.py` на московском сервере. Это отдельный проект
VPN-server: обновление checkout сайта не доставляет этот файл. На **Москве**, под root:

```bash
cd /root/VPN-server
git status --short
git pull --ff-only
test -f scripts/relay.py && echo 'Установщик ретранслятора найден'
```

Используйте фактический путь checkout. Если файл ещё не опубликован в Git,
скопируйте его с компьютера, выполнив **в PowerShell на компьютере**:

```powershell
scp "D:\VPN-server\scripts\relay.py" root@62.113.42.137:/root/VPN-server/scripts/relay.py
```

Получение файла ещё не устанавливает службу. После него выполните `install` ниже.
Обновить весь VPN-контейнер для ретрансляции не требуется. Из checkout `VPN-server`
на **Москве**, под root, пример для исторического тестового порта 14443:

```bash
python3 scripts/relay.py install \
  --public-ip 62.113.42.137 --interface eth0 \
  --listen-port 14443 \
  --target-ip 83.171.225.80 --target-port 443 \
  --adopt-test
```

`--adopt-test` нужен для перехода с ручного теста из чата: после установки новых правил
он удалит только три точных правила этого маршрута с комментарием `aegis-relay-test`.
Повторный запуск с теми же параметрами не дублирует маршрут или правила.
Если порт занят процессом, опубликован Docker или назначен другому маршруту,
установщик откажется. Для изменения назначения порта сначала удалите старый маршрут.

Порт должен совпадать с настройкой сайта. В текущей настройке FRA используется
**14446**: для неё замените `--listen-port 14443` на `--listen-port 14446` и уберите
`--adopt-test`, поскольку временный тест использовал другой порт.
После последующего `git pull` для обновления уже работающей службы повторите
`install` из checkout: он обновляет отдельную установленную копию программы.

В firewall панели хостинга разрешите входящий `14443/UDP`. На иностранном VPS должны
приниматься пакеты VPN-порта с московского IP. Установщик не меняет firewall хостинга.

Установщик сохраняет:

- `/etc/aegis-relay/routes.json`: все маршруты (включить в резервные копии);
- `/usr/local/lib/aegis-relay/relay.py`: отдельную копию управляющего скрипта;
- `/etc/systemd/system/aegis-relay.service`: службу с автозапуском;
- `/etc/sysctl.d/70-aegis-relay.conf`: постоянное включение IPv4 forwarding.

Служба каждые 15 секунд проверяет наличие своих правил и восстанавливает отсутствующие,
в том числе после перезапуска Docker. При остановке службы удаляются только её точные
правила; при запуске они создаются снова. Перезапуск службы кратковременно прерывает
ретрансляцию. Docker-цепочки не очищаются, существующие политики firewall не меняются.

Новый маршрут для другого иностранного сервера добавляется той же командой с другим
`--listen-port` и фактическим `--target-ip`. Например, следующий порт — `14444`.
Не направляйте один порт сразу на несколько иностранных серверов: у них разные ключи.

## Проверка

```bash
python3 /usr/local/lib/aegis-relay/relay.py status
systemctl status aegis-relay --no-pager
journalctl -u aegis-relay -n 50 --no-pager
```

Для каждого маршрута ожидается `"rules_present": true`, служба — `active`.
Это проверяет правила, а не реальное VPN-рукопожатие. На клиенте используйте копию
профиля иностранного сервера с `Endpoint = 62.113.42.137:14443`. Проверьте рукопожатие,
открытие сайтов и иностранный выходной IP из проблемной сети. Прямой вариант и копию
с теми же ключами не включайте одновременно.

Для проверки восстановления правил можно перезапустить только службу:

```bash
systemctl restart aegis-relay
python3 /usr/local/lib/aegis-relay/relay.py status
```

Сохранение после перезагрузки хоста проверяйте в согласованное время: перезагрузка
Москвы также прерывает сайт и локальный VPN. Проверки systemd не заменяют этот тест.

## Подключение к сайту

Обновите сайт с миграцией `0019_vpn_relay`. В `/app/vpn` у **существующего иностранного
сервера** сохраните адрес Москвы `62.113.42.137`, порт `14443` и включите «Доступно
клиентам». Сайт не устанавливает правила на VPS: сначала выполните установку выше.

Не меняйте `.env` иностранного агента и не регистрируйте его повторно.
Подробная инструкция сайта: [маршрут через Москву](https://github.com/JohnBlec/VPN_Web-app/blob/main/docs/relay.md).

## Откат одного маршрута

Сначала отключите «Доступно клиентам» в админке, затем на Москве:

```bash
python3 /usr/local/lib/aegis-relay/relay.py remove --listen-port 14443
```

Удаляются только правила выбранного маршрута. Остальные маршруты работают дальше.
Когда удалён последний маршрут, служба отключается и её sysctl-файл удаляется.
Само IPv4 forwarding остаётся включённым, поскольку оно нужно существующим Docker/VPN.
Копия программы, unit и пустой файл маршрутов остаются для повторной установки.
Для возврата к прямому подключению включите исходный профиль иностранного сервера.
