# VPN-сервер Aegis: AmneziaWG + Docker Compose

Для размещения **сайта** на Ubuntu 22.04 с HTTPS, включая совместное размещение с этим VPN
и подключение других VPN VPS, используйте
[production-инструкцию сайта](https://github.com/JohnBlec/VPN_Web-app/blob/main/docs/production-ubuntu.md).
Этот каталог отвечает за VPN; переустанавливать его при запуске сайта не требуется.

Этот каталог содержит отдельный VPN-сервер для вашего сайта: AmneziaWG, закрытый API
управления устройствами, постоянное хранилище и инструкции обслуживания.
При обновлении пересоздаётся контейнер; клиенты, адреса и ключи остаются на диске.
Старый WireGuard-сервер не требуется.

Серверный комплект и интеграция Django реализованы. Сайт поддерживает устройства,
выдачу `.conf` и QR-кода, статистику трафика и синхронизацию подписок через worker.
При первом подключении VPS зарегистрируйте API на backend и запустите worker по
[инструкции сайта](https://github.com/JohnBlec/VPN_Web-app/blob/main/docs/vpn-integration.md).
На каждом новом VPS проверьте реальное VPN-соединение до выдачи профилей клиентам.

## Что запускается

```text
AmneziaWG-клиент → публичный UDP-порт VPS → VPN-контейнер → интернет IPv4

Django backend → защищённый SSH-туннель → 127.0.0.1:8787 → API VPN-контейнера
                                                        ↓
                                              data/state.json
```

- AmneziaWG Go **3.1**, исходники зафиксированы по Git commit.
- `awg` управляет интерфейсом; изменения пиров применяются через `syncconf` без
  перезапуска всех VPN-соединений.
- Userspace-реализация: модуль AmneziaWG в ядро хоста не устанавливается.
- Контейнеру нужны `/dev/net/tun` и `NET_ADMIN` в его собственном сетевом пространстве.
  `privileged`, `network_mode: host`, доступ к Docker socket и `SYS_MODULE` не используются.
- API с bearer-токеном опубликован только на loopback хоста. Публичной админ-панели нет.
- Клиентские приватные ключи и PSK зашифрованы отдельным Fernet-ключом. Серверный
  приватный ключ и общий ключ защиты заголовков находятся в защищённом файле состояния;
  весь бэкап дополнительно шифруется `age`.
- Полный туннель IPv4. IPv6 направляется в туннель и блокируется, чтобы не выходить
  напрямую через провайдера. Доступ к приватным сетям VPS и между VPN-клиентами закрыт.

## Что сохранять

| Путь | Содержимое | Поведение при пересоздании |
|---|---|---|
| `data/state.json` | Серверные ключи, настройки протокола, устройства, адреса | Сохраняется |
| `data/.initialized` | Защита от случайного создания нового сервера при потере state | Сохраняется |
| `data/traffic.sqlite3` | Дневной трафик, рукопожатия и идентификатор источника статистики | Сохраняется; включать весь `data` в бэкап |
| `secrets/client_key` | Ключ расшифровки клиентских ключей | Сохраняется, не генерировать повторно |
| `secrets/agent_token` | Токен серверного API | Сохраняется |
| `.env` | Адрес VPS, внешний порт, версии исходников | Сохраняется |
| `exports/` | Выгруженные клиентские `.conf`, если вы их сохраняете | Только локальные файлы, не Git |
| `backups/` | Зашифрованные резервные копии | Копировать за пределы VPS |

Это bind mounts, а не содержимое слоя контейнера. Удаление контейнера не удаляет эти
каталоги. Удаление самого каталога развёртывания уничтожит их вместе с ключами.
Не выполняйте первоначальный `setup.py` при обычном обновлении.

## Проверки комплекта

Локально из корня checkout: установить `python -m pip install -r requirements-dev.txt`,
затем `python -m unittest discover -s tests -v`,
проверка синтаксиса shell и `docker compose config --quiet`.
На VPS: `bash scripts/smoke-test.sh` и реальное подключение телефона/ПК.

Локальные тесты не подтверждают TUN, NAT и прохождение VPN-трафика.
Сборку Linux-образа и реальное подключение проверяйте на целевом VPS до перевода клиентов.

Версии, ограничения совместимости и первичные источники: [docs/SOURCES.md](docs/SOURCES.md).
