# Диагностика

Все команды выполняются из каталога Compose VPN на VPS (в примерах `/opt/aegis-vpn`;
для установки в `/root/VPN-server` используйте этот путь). Не публикуйте `state.json`,
`.conf`, токены, вывод `awg showconf` или `awg show ... dump`: они содержат секреты.

```bash
docker compose ps -a
docker compose logs --tail 100 vpn
docker compose exec -T vpn python3 /opt/aegis/agent.py health
docker compose exec -T vpn awg show awg0 latest-handshakes
docker compose exec -T vpn awg show awg0 transfer
```

| Симптом | Что проверить |
|---|---|
| Ошибка сборки / GitHub недоступен | DNS и интернет VPS, свободный диск, полный лог стадии сборки. Не заменять закреплённый commit случайным образом |
| `/dev/net/tun` отсутствует | `test -c /dev/net/tun`, `modprobe tun`, поддержка TUN у провайдера |
| `Operation not permitted` при старте | Обычный rootful Docker, NET_ADMIN и TUN из Compose, ограничения LXC/OpenVZ. Не включать privileged как обход |
| Контейнер перезапускается после изменения `.env` | Вернуть исходную подсеть; проверить наличие обоих secrets и корректный endpoint. Ключ шифрования должен соответствовать данным |
| `JSONDecodeError` / `InvalidToken` при старте | Повреждён state или подменён client_key. Остановить контейнер, восстановить согласованный бэкап. Не удалять данные ради запуска |
| HTTP 401 | Проверить машинный токен и заголовок Bearer; токен не должен попадать во frontend |
| HTTP 503 | Подождать локальную сверку (15 секунд), проверить контейнер. Повторять запрос с тем же ID, не создавать новый |
| HTTP 409 при создании | ID уже занят другим именем или исчерпаны адреса; отключённые устройства также занимают адрес |
| VPN healthy, handshake отсутствует | UDP-порт в firewall провайдера, endpoint/DNS A-запись, отсутствие CDN proxy, актуальность клиентского приложения AWG 3.1 |
| Handshake есть, интернет не работает | Разрешён исходящий трафик VPS, NAT/forwarding, DNS, конфликт подсетей. Проверить на другой сети клиента |
| Некоторые сайты зависают | Проверить MTU (по умолчанию 1280), DNS и ограничения сети; после изменения MTU/DNS скачать профиль заново |
| IPv6-сайты без IPv4 недоступны | Ожидаемо: этот вариант блокирует IPv6 внутри туннеля. Для IPv6-интернета нужна отдельная маршрутизация |
| Сайт не достаёт API | Проверить SSH-туннель и его known_hosts; localhost контейнера отличается от localhost хоста |
| VPN работает, статистика недоступна | Обновить сайт и агент; проверить `traffic.py` в образе, журнал контейнера, наличие и доступность `data/traffic.sqlite3`. Не удалять журнал для исправления ошибки |

Для проверки правил внутри контейнера без вывода ключей:

```bash
docker compose exec -T vpn ip -brief address
docker compose exec -T vpn ip route
docker compose exec -T vpn iptables -S
docker compose exec -T vpn iptables -t nat -S
docker compose exec -T vpn ip6tables -S
```

Не подключайте контейнер VPN к дополнительным Docker-сетям без пересмотра правил:
выходящий интерфейс в этом комплекте — `eth0`. Не меняйте peers вручную командой
`awg set`: сверка перезапишет изменения из сохранённого состояния.

Проверка SSH: `ssh -v -NT ...` с теми же параметрами туннеля; при смене VPS сверить
новый fingerprint через доверенную консоль, затем обновить known_hosts. Не отключать
проверку ключа хоста. API не нужно открывать наружу для диагностики.

Если Docker отмечает контейнер unhealthy, но процесс работает, сам Docker его не
перезапускает по этому признаку. Исправьте причину; затем при необходимости выполните
`docker compose restart vpn`. Restart policy восстанавливает завершившийся процесс
и запуск после перезагрузки хоста, но не заменяет мониторинг.
